## ติดตั้งลงมือถือ

ติดตั้งแล้วแอปจะมีไอคอนบนหน้าจอโฮม เปิดได้เต็มจอเหมือนแอปทั่วไป

| มือถือ | วิธีติดตั้ง |
|---|---|
| **Android (Chrome)** | เปิดลิงก์ → แตะ **⋮** มุมขวาบน → **ติดตั้งแอป** หรือ **เพิ่มลงในหน้าจอหลัก** |
| **iPhone (Safari)** | เปิดลิงก์ด้วย **Safari** → แตะปุ่ม **แชร์** (สี่เหลี่ยมมีลูกศรขึ้น) → **เพิ่มไปยังหน้าจอโฮม** |

> ครั้งแรกที่เปิด แอปจะถามสิทธิ์ **ตำแหน่ง** ให้กด **อนุญาต** เพื่อใช้ GPS ปักจุดและคำนวณระยะทาง

## เข้าสู่ระบบ

1. เลือก **การไฟฟ้า** เช่น กฟส.คำชะอี
2. เลือกบทบาท **ผู้ตรวจ** หรือ **ผู้รับจ้าง**
3. กรอก **ชื่อผู้ใช้** และ **รหัสผ่าน** ที่ได้รับจากการไฟฟ้า (ไม่ต้องใช้อีเมล)

ระบบจะจำการเข้าสู่ระบบไว้ ครั้งต่อไปเปิดแอปแล้วเข้าหน้าหลักได้ทันที ถ้าจะสลับผู้ใช้ให้กด **ออก** ที่มุมขวาบน

> ผู้รับจ้างจะเห็นเฉพาะ Feeder ที่การไฟฟ้ามอบหมายให้เท่านั้น

## สำหรับผู้ตรวจ กฟภ.

### 1. นำเข้า Feeder จากไฟล์ KMZ
1. หน้าหลัก → **+ นำเข้า Feeder**
2. เลือกได้ 3 แบบ
   - **เลือกโฟลเดอร์** (แนะนำ) — 1 โฟลเดอร์ = 1 Feeder ตั้งชื่อเป็น `รหัสFeeder ชื่อสาย` เช่น `MDA03R-04 ไลน์เหล่าสร้างถ่อ`
   - **เลือกหลายไฟล์ KMZ**
   - **เลือกไฟล์ .zip** ของโฟลเดอร์
3. ตรวจตารางช่วงและแผนที่ย่อ แก้รหัส Feeder หรือชื่อสายได้ เลือก **ผู้รับจ้าง** ที่จะเห็นงานนี้
4. ถ้ามี Feeder รหัสเดียวกันอยู่แล้ว ระบบจะให้เลือก
   - **เพิ่มช่วงใหม่** — เก็บผลตรวจเดิมไว้ ช่วงที่ลำดับซ้ำจะถูกข้าม
   - **แทนที่ทั้งหมด** — ⚠ ลบช่วงและจุดบกพร่องเดิมของ Feeder นี้ทั้งหมด
5. กด **ยืนยันนำเข้า**

ระบบอ่านข้อมูลจากไฟล์ KMZ ให้อัตโนมัติ ได้แก่ เส้นแนวสาย, ความยาว (กม.), แรงดัน, จำนวนต้นตามแผน, ความหนาแน่น และจำนวนต้นราคากลาง ไฟล์ที่อ่านไม่ได้จะแจ้งชื่อไฟล์พร้อมเหตุผล

> การนำเข้าต้องทำตอนมีสัญญาณ

### 2. ออกตรวจ
1. กด **แผนที่** ที่การ์ด Feeder
2. เส้นช่วงงานตัดมีสีตามสถานะ: **เส้นประเทา** = ยังไม่ตรวจ · **แดง** = มีจุดบกพร่องค้าง · **เขียว** = ผ่าน (กด **สัญลักษณ์** ที่มุมซ้ายบนเพื่อดูคำอธิบายทั้งหมด)
3. ช่วงที่ตัดเรียบร้อยดี → แตะช่วงนั้น → **✓ ผ่านทั้งช่วง**

### 3. ปักจุดบกพร่อง
1. ยืนตรงจุดที่พบปัญหา → กด **+ ปักจุดบกพร่องที่นี่**
2. ระบบใช้พิกัด GPS แล้ว **เลือกช่วงที่ใกล้ที่สุดให้อัตโนมัติ** ถ้าหมุดอยู่ห่างแนวสายเกิน 50 ม. จะมีคำเตือน
   - ปรับตำแหน่งได้ด้วยการ **ลากหมุดสีม่วง** หรือแตะบนแผนที่
   - เลือกช่วงเองได้จากปุ่มช่วงที่อยู่ใต้กล่องช่วงงานตัด
3. **ถ่ายรูป** (ระบบย่อรูปในเครื่องก่อนส่ง ประหยัดเน็ต)
4. เลือก **ประเภทปัญหา** (จำเป็น) ใส่หมายเหตุ และเลือกรอบการตรวจ
5. กด **บันทึกจุดบกพร่อง** — ได้รหัสจุด เช่น `D-0012`

### 4. ตรวจผลการแก้ไข
- เมื่อผู้รับจ้างส่งหลักฐาน จะมี **ตัวเลขที่กระดิ่ง 🔔** และข้อความแจ้งทันที ไม่ต้องรีเฟรช
- เปิดจุดนั้นเพื่อดู **รูปก่อน/หลัง** และ **ประวัติการตรวจ**
- กด **✓ ผ่าน** หรือ **✕ ไม่ผ่าน ส่งกลับ** (ไม่ผ่านต้องระบุเหตุผล และระบบจะนับเป็นรอบตรวจถัดไป)

### 5. รายงานและปิดงาน
- **ความคืบหน้า** — ภาพรวมรายสาย สัดส่วนช่วงที่ผ่าน จุดบกพร่องแยกตามสถานะ/ประเภท และผลแต่ละรอบ
- **รายงาน** → **พิมพ์ / ส่งออก PDF** — ได้รายงาน A4 พร้อมช่องลงนาม (ใน Chrome เลือกปลายทางเป็น **บันทึกเป็น PDF**)
- เมื่อ **ทุกช่วงผ่าน** ปุ่ม **✓ ปิดงาน Feeder** จะขึ้นที่หน้ารายงาน

### 6. ลบงาน
หน้ารายงาน → **ลบงาน** (มุมขวา) → ยืนยัน 2 ชั้น
1. ระบบสรุปสิ่งที่จะถูกลบ (ช่วงงานตัด, จุดบกพร่องพร้อมประวัติ, รูปถ่าย) → **ต่อไป**
2. กรอก **รหัสยืนยันการลบงาน** (ขอจากผู้ดูแลระบบ) → **ลบถาวร**

⚠ ลบแล้ว **กู้คืนไม่ได้** · ต้องมีสัญญาณ และต้องไม่มีข้อมูลรอส่งค้างอยู่

## สำหรับผู้รับจ้าง

1. หน้าหลักจะแสดงจำนวน **จุดที่ต้องแก้ไข** · **ส่งแล้ว รอตรวจ** · **ผ่านแล้ว**
2. กด **ดูจุดที่ต้องแก้** ที่การ์ด Feeder — รายการจัดกลุ่มตามช่วง **เรียงจากใกล้ตัวคุณที่สุด**
3. กด **นำทาง** เพื่อเปิด Google Maps ไปยังจุดนั้น
4. แก้ไขเสร็จ → **ส่งหลักฐานการแก้ไข**
   - ถ่ายรูปหลังแก้ไขอย่างน้อย 1 รูป (แนะนำให้ถ่ายมุมเดียวกับรูปก่อนแก้)
   - ใส่หมายเหตุ → **ส่งหลักฐาน**
5. รอผู้ตรวจตรวจซ้ำ ถ้า **ไม่ผ่าน** จะเห็นเหตุผลใต้รายการ ให้แก้ไขแล้วส่งใหม่

## ใช้งานตอนไม่มีสัญญาณ

แอปออกแบบให้ทำงานในพื้นที่ที่ไม่มีสัญญาณได้

- **บันทึกได้ตามปกติ** ทั้งปักจุด, ถ่ายรูป, ผ่านทั้งช่วง, ส่งหลักฐาน และตัดสินผ่าน/ไม่ผ่าน ข้อมูลจะเก็บไว้ในเครื่องพร้อมป้าย **รอส่ง**
- **ส่งอัตโนมัติ** เมื่อกลับมามีสัญญาณ (หรือแตะป้าย **ออนไลน์** มุมขวาบนเพื่อลองส่งทันที) เวลาที่บันทึกจะเป็นเวลาที่กดจริง ไม่ใช่เวลาที่ส่ง
- **เปิดแอปตอนไม่มีเน็ตได้** และจะเห็นข้อมูลชุดล่าสุดที่โหลดไว้

⚠ **ข้อควรรู้**
- ต้อง **เข้าสู่ระบบและเปิดแอปตอนมีสัญญาณอย่างน้อย 1 ครั้ง** ก่อนออกพื้นที่
- แผนที่ออฟไลน์จะเห็นเฉพาะบริเวณที่ **เคยเปิดดูตอนมีสัญญาณ** — ก่อนออกพื้นที่ให้เปิดแผนที่ Feeder แล้วซูมดูแนวสายให้ทั่ว
- ถ้ายังมีข้อมูลรอส่ง ระบบจะ **ไม่ให้ออกจากระบบ** (เพื่อไม่ให้ข้อมูลหาย) ให้ต่อเน็ตจนส่งครบก่อน
- การนำเข้า Feeder และการเข้าสู่ระบบครั้งแรกต้องมีสัญญาณ

## สำหรับผู้ดูแลระบบ

ข้อมูลทั้งหมดเก็บที่ **Supabase**

### ติดตั้งฐานข้อมูล (ครั้งแรก)
Supabase Dashboard → **SQL Editor** → วางเนื้อหาไฟล์ [`supabase/schema.sql`](supabase/schema.sql) ทั้งไฟล์ → **Run** (รันซ้ำได้ ไม่ทำลายข้อมูลเดิม)

### เพิ่มผู้ใช้
ผู้ใช้ไม่ต้องมีอีเมลจริง ระบบใช้อีเมลภายในรูปแบบ `ชื่อผู้ใช้@รหัสการไฟฟ้า.local` (ตัวอย่างด้านล่างเป็นชื่อสมมติ)

1. Dashboard → **Authentication → Users → Add user → Create new user**
   - Email: เช่น `somchai.j@kce.local`
   - Password: ตั้งให้ผู้ใช้
   - ✓ **Auto Confirm User**
2. SQL Editor → ผูกโปรไฟล์ (**ขั้นตอนนี้จำเป็น** ไม่งั้นจะเข้าระบบไม่ได้)

```sql
-- ผู้ตรวจ
insert into profiles (id, office_id, username, full_name, role, company)
select id, 'kce', 'somchai.j', 'สมชาย ใจดี', 'inspector', null
from auth.users where email = 'somchai.j@kce.local';

-- ผู้รับจ้าง (company = ชื่อที่จะแสดงในระบบและรายงาน)
insert into profiles (id, office_id, username, full_name, role, company)
select id, 'kce', 'romyen.co', 'ผู้ประสานงาน', 'contractor', 'หจก. ร่มเย็นการโยธา'
from auth.users where email = 'romyen.co@kce.local';
```

### เปลี่ยนชื่อผู้ใช้
ต้องเปลี่ยนทั้งอีเมลภายในและโปรไฟล์ (ตัวอย่าง: เปลี่ยน `somchai.j` เป็น `somchai`)
```sql
update auth.users set email = 'somchai@kce.local' where email = 'somchai.j@kce.local';
update auth.identities set identity_data = jsonb_set(identity_data, '{email}', '"somchai@kce.local"')
  where provider = 'email' and user_id = (select id from auth.users where email = 'somchai@kce.local');
update profiles set username = 'somchai' where office_id = 'kce' and username = 'somchai.j';
```
เปลี่ยนรหัสผ่าน: Dashboard → Authentication → Users → เลือกผู้ใช้ → **Reset password** หรือแก้ในเมนูของผู้ใช้นั้น

### เพิ่มการไฟฟ้าแห่งใหม่
```sql
insert into offices (id, name) values ('xxx', 'กฟส.ชื่อใหม่');
```
`id` คือรหัสสั้นภาษาอังกฤษ ใช้ต่อท้ายอีเมลผู้ใช้ของการไฟฟ้านั้น ผู้ใช้แต่ละการไฟฟ้าจะเห็นเฉพาะข้อมูลของตนเอง

### ลบ Feeder
```sql
delete from feeders where code = 'MDA03R-04';   -- ลบช่วง จุดบกพร่อง และประวัติตามไปด้วย
```
ไฟล์รูปใน **Storage → photos** ต้องลบเองถ้าต้องการคืนพื้นที่

### สิทธิ์การเข้าถึง (บังคับที่ฐานข้อมูล)
| | ผู้ตรวจ | ผู้รับจ้าง |
|---|---|---|
| เห็น Feeder | ทุก Feeder ในการไฟฟ้าตน | เฉพาะที่มอบหมาย |
| นำเข้า / ปักจุด / ตัดสิน / ปิดงาน | ✓ | ✗ |

| แก้หรือลบข้อมูลของผู้ตรวจ | ✓ | ✗ |

## สำหรับนักพัฒนา

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | แอปทั้งหมดในไฟล์เดียว (vanilla JS · Leaflet · JSZip · supabase-js) |
| `sw.js` | Service Worker — เก็บตัวแอป ไลบรารี ฟอนต์ แผนที่ และรูปไว้ใช้ออฟไลน์ |
| `manifest.webmanifest`, `icons/` | PWA (ติดตั้งลงหน้าจอโฮม) |
| `supabase/schema.sql` | ตาราง · RLS · trigger · storage · realtime |
| `tools/extract-prototype.js` | แตกไฟล์ต้นแบบ Claude Design ออกมาอ่าน |
| `tools/test-parse-desc.js` | ทดสอบตัวอ่านข้อมูล KMZ: `node tools/test-parse-desc.js` |

- **โหมดสาธิต:** เปิด `index.html?demo` — ใช้ข้อมูลจำลองในเครื่อง ไม่แตะฐานข้อมูลจริง เหมาะกับการสาธิตหรือทดสอบหน้าตา
- **ทดสอบในเครื่อง:** ต้องเปิดผ่าน `http://localhost` หรือ https (GPS และ Service Worker ใช้กับการดับเบิลคลิกเปิดไฟล์ไม่ได้)
- **อัปเดตเว็บ:** push ขึ้น branch `main` → GitHub Pages อัปเดตใน 1–2 นาที ถ้าเปลี่ยนไฟล์ในรายการ cache ของ `sw.js` ให้เปลี่ยนเลข `CACHE` ด้วย
- **คีย์:** ใน `index.html` ใช้เฉพาะ publishable key (เปิดเผยได้ ข้อมูลป้องกันด้วย RLS) — **ห้ามใส่ service_role key ในไฟล์ใดๆ**
